# 受保护房间读路径审查

以下是对现有 Gateway 的读路径审查，最初在三补丁树 `da14700bdaef6fd664d9f98e1153a15cce142ea2` 上完成。独立本地试验进程的读写入口和存储见[本地房间观察页](local-room-observer.md)。

| 入口 | 当前行为 | 接入读授权需要覆盖的边界 |
| --- | --- | --- |
| `GET /api/events` | [同一历史处理器](../internal/gateway/history.go)按请求房间查询事件、快照边界、总数和分页。 | 在读数据库前检查房间权限，涵盖首屏、旧页和拉取新事件。 |
| `GET /api/events/export.html` | 与列表共用历史处理器，可独立下载全量或指定范围。 | 使用与列表相同的读授权，路径在数据查询前收口。已有脱敏和转义继续生效。 |
| `GET /api/rooms/presence` | [在线快照](../internal/presence/presence.go)同时返回连接与持久化发言摘要。 | 在读取快照及发言摘要前授权，即使房间无人在线。 |
| `/ws` 观察 WebSocket | [升级后订阅](../internal/gateway/ws.go)，先从存储回放，再消费实时队列。观察连接拒绝写入。 | 在升级、订阅和回放之前授权，凭据到期时关闭连接，阻断到期后的回放与实时写帧。 |
| `/api/v1/agent/connect` | 与观察 WebSocket 共用订阅和回放，而且在 `agent.hello` 之前执行。 | 同样先授权。当前共享 Agent 凭据没有房间身份，受保护房间需要在升级前拒绝该类连接。Chat MCP 和级联继承此边界。 |
| 实时事件总线 | [EventBus](../internal/eventbus/bus.go)按房间分流，空房间订阅可匹配所有房间。生产订阅点在 WebSocket handler。 | 仅创建已授权的准确房间订阅，禁止将受保护流转发到全局订阅。 |
| 房间列表和全局目录 | 当前 Gateway 没有房间列表路由。观察页输入房间 ID。 `/api/agents`、`/api/capabilities` 和 `/api/capability-resolve` 是全局 Agent 或能力目录。 | 本片维持无房间列表。全局目录不能用作房间成员或点名权限的依据，目录响应不能附带受保护房间的成员关系。 |
| 旧调用及传输 API | [调用服务](../internal/p1/service.go)和[传输服务](../internal/transfer/service.go)可按提交的 `room_id` 写入事件。后续请求按对象 ID 查找并返回含房间的元数据，传输还可发布到总线。 | 除 URL 查询入口外，还须在这些请求写入前和返回已有对象前阻止旧凭据跨入受保护房间。 |
| 计划、任务、看板、私有会话和 Relay | [P2 服务](../internal/p2/service.go)将这些事件写入空房间，全局目录由 Registry 提供。Relay 按票据配对传输字节，不读取房间事件。 | 保持全局空房间与受保护房间分离。用集成测试确认现有路径无法到达受保护事件和元数据。 |

## 过期和保留数据

`humanauth.AuthorizeRead` 只在当前凭据有准确房间读权限时返回租约。租约的截止时间取自服务端凭据，连接心跳和客户端帧无法延长。接到 Gateway 时，应用应把租约 context 传给回放，把截止时间作为每次写帧的上限，并在到期或父请求结束时关闭 socket 和清理订阅。需要覆盖无流量连接、回放进行中、并发实时写入以及过期重连。

单纯按当前配置开关在共享事件表前分流会留下回退风险。一旦取消房间保护或回滚到旧 Gateway，同名房间在旧历史、导出和回放中仍可被读取。最小的安全试点可为新测试房使用独立事件存储，旧路由没有该存储的访问路径。保护已有房间时，应先明确历史归属和迁移或回退策略。

## 接线门槛

本机缺少锁定的 `modernc.org/sqlite@v1.34.5`，无法在当前配置下运行 Gateway 和 server 的 SQLite 集成用例。读租约的回环 WebSocket 测试只验证租约与关闭机制，不能证明现有 Gateway 回放和响应都已接入。完成接线前，应在有锁定依赖的隔离环境中用两个合成房间和临时数据库验证上表各入口。覆盖旧凭据拒绝、跨房拒绝、过期后的回放和广播、无权限的旧 API 返回，以及关闭功能或回退时的已存数据隔离。

上述读边界全部通过后，才加同源的人类写入口。服务端从授权取得发送者，单点名目标必须是房间内可验证的稳定 ID。只在持久化提交后广播和返回回执，观察页按纯文本显示。此片不提供全员点名。
